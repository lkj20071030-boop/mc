# 方块世界：第一阶段基础可玩版

项目目录：`D:\我的世界小游戏`。技术栈：Three.js、JavaScript、Vite、HTML / CSS。

已实现：20×20 单层草地、第一人称视角、WASD 移动、重力、跳跃、方块碰撞、准星、五格射线选中、破坏、放置、草/泥土/石头选择栏。代码按功能拆分，关键逻辑有中文注释。

## 运行

最简单：双击项目目录中的 `启动游戏.cmd`。运行时保持终端窗口打开。

在 VS Code 中：选择“文件 → 打开文件夹”，打开项目目录，然后在 PowerShell 终端运行：

```powershell
cd 'D:\我的世界小游戏'
.\npm.cmd run dev
```

打开终端显示的本地地址，通常为 http://127.0.0.1:5173/ 。点击“进入世界”开始，按 Esc 暂停。Ctrl+C 停止服务器。

依赖已经安装；若以后删除了 node_modules，先运行：

```powershell
.\npm.cmd install
```

本机的 Node.js 与 npm 放在项目内的 `.tools` 文件夹。根目录的 `npm.cmd` 会调用它们，不修改系统 PATH。PowerShell 必须带上 `.\`；若电脑已有兼容的 Node.js，也可以使用标准 `npm run dev` 命令。

不要直接双击 index.html，也不要把 dist/index.html 作为本地文件打开；应通过 Vite 的 HTTP 地址访问。

## 操作

| 输入 | 效果 |
| --- | --- |
| W / A / S / D | 前 / 左 / 后 / 右，方向跟随视角 |
| 鼠标 | 转动第一人称视角 |
| 空格 | 落地后跳跃一次 |
| 左键 | 破坏准星选中的方块 |
| 右键 | 在选中方块的表面旁放置新方块 |
| 1 / 2 / 3 | 草方块 / 泥土 / 石头 |
| Esc | 暂停并释放鼠标 |
| 点击“继续游戏” | 恢复游戏 |

部分内置预览窗口禁止锁定鼠标，游戏会自动使用**拖动转向模式**：按住鼠标拖动改变视角，单击左键破坏、单击右键放置。方块操作仍以屏幕中央准星为准，不以鼠标光标所在位置为准。页面右下角会显示当前操作方式。

在支持 Pointer Lock 的 Chrome / Edge 独立窗口中，点击进入后可直接移动鼠标转向。离开标签页或窗口失去焦点时自动暂停，避免松开按键后仍持续移动。

## 正常画面与最短试玩流程

1. 进入后站在草地上，屏幕中央有准星，底部有三个方块格。
2. 看向附近方块，出现浅色选中边框及方块名称、整数坐标。
3. 按 3 选择石头，再按右键：地面上增加一个石头方块，右上角数量增加。
4. 按 2，瞄准石头的一侧右键：旁边增加泥土方块。
5. 左键破坏：选中的方块消失，数量减少，后面的目标可以被选中。
6. 向新放的方块走去，身体会被挡住；按空格可以跳上一个方块高的平台。
7. 走出地面或挖穿脚下会下落；低于 -20 时自动回到安全出生点。
8. 按 Esc：显示菜单，移动和方块操作暂停；继续后保留当前建造结果。

如果出生点的地面被挖掉，会补回一块草方块；如果出生点堆高，会回到那一列最高方块上方。

## 关键计算为什么这样写

- **坐标**：方块边长为 1，整数坐标代表中心，边界为中心 ±0.5。地面中心 Y=0，所以上表面是 Y=0.5。
- **玩家位置**：position 是脚底中心，身体宽 0.6、高 1.8，眼睛比脚底高 1.62。把身体和相机分开，能正确处理撞头和脚底落地。
- **时间**：毫秒除以 1000 得到秒，位移=速度×时间。正常帧率下走路速度不随帧率变化；对超过 0.05 秒的长帧做限制，优先避免卡顿后的大幅跳动。
- **斜向移动**：W+D 的原始向量长度是 √2；normalize 将长度变成 1，斜着走不额外加速。
- **朝向**：正弦和余弦把前进/左右方向旋转到玩家朝向，抬头不会变成飞行。
- **重力**：向上为正，速度每帧减去重力×时间，再用速度计算位移；落地或撞头后将竖直速度清零。
- **跳跃**：落地后给一个向上的速度；空中再次按空格不会重设速度。
- **碰撞**：玩家与方块都是轴对齐长方体，三个坐标轴都重叠才算碰撞。分别处理 X、Z、Y，因此撞墙时仍能沿墙移动。
- **防穿透**：把大位移分成最多 0.2 单位的小步，每步都检查附近方块。
- **放置**：选中方块中心+被击中面的法线=紧邻方块的中心。例如上表面法线为 (0,1,0)，放置高度就增加 1。

## Three.js API 速查

| API | 用途 |
| --- | --- |
| Scene / Group | 场景容器 / 一组方块模型的容器 |
| PerspectiveCamera | 近大远小的透视相机 |
| WebGLRenderer / render | 把三维场景画到 HTML canvas |
| BoxGeometry / Mesh | 定义立方体形状 / 组合形状与材质 |
| MeshLambertMaterial | 受光照影响的简单表面 |
| HemisphereLight / DirectionalLight | 天空补光 / 平行光 |
| Vector3 / normalize | 三维位置与方向 / 把方向长度变成 1 |
| Raycaster.setFromCamera | 从摄像机穿过屏幕中心发射检测射线 |
| intersectObjects | 检测方块，按距离返回命中结果 |
| EdgesGeometry / LineSegments | 提取并绘制方块棱边 |
| updateMatrixWorld | 更新模型或相机的世界变换，射线使用最新位置 |
| setAnimationLoop | 每帧执行游戏更新和绘制 |
| dispose | 释放不再使用的显卡资源 |

Pointer Lock 是浏览器提供的 API，不是 Three.js API。本项目自己计算水平与俯仰角，便于阅读，不引入额外控制器依赖。

官方参考：[Three.js 文档](https://threejs.org/docs/) · [Vite 入门](https://vite.dev/guide/)。

## 自动测试与构建

```powershell
.\npm.cmd test
.\npm.cmd run build
.\npm.cmd run preview
```

- test：运行17项逻辑测试，覆盖落地、跳跃、撞头、正负方向墙体、高速下落、沿墙滑动、负坐标、复位、射线遮挡、五格距离、六面放置和身体重叠保护。
- build：输出 dist。Three.js 引擎会导致“大于500 kB”的体积提示，提示不代表构建失败。
- preview：检查构建产物，使用终端显示的地址访问。
- 运行时依赖只有 Three.js，开发依赖只有 Vite；测试使用 Node.js 内置测试工具。

## 报错先检查哪里

| 情况 | 优先检查 |
| --- | --- |
| npm 命令不存在 | 切到项目目录，执行 `.\npm.cmd`；不要遗漏前面的 `.\` |
| 找不到 node.exe / npm-cli.js | 检查 .tools 是否还在；或安装兼容 Node.js，使用系统 npm |
| 找不到 vite 或 three | 执行 `.\npm.cmd install` |
| 页面无法打开 | 保持开发服务器终端开启，使用终端显示的实际端口 |
| 页面还是旧画面 | 刷新；必要时 Ctrl+C 停止后重新运行 dev，确认打开的是这个项目 |
| 画面黑屏或只有菜单 | F12 → Console，先看第一条红色错误；检查 WebGL / 图形加速 |
| 无法锁定鼠标 | 观察右下角是否为拖动模式；也可以用独立 Chrome / Edge 窗口 |
| 键盘无反应 | 先点击“进入世界”，确认页面获得焦点；切换窗口后需要继续游戏 |
| 没有选中框 | 目标必须在5格内；低头看附近地面，检查准星下方文字 |
| 右键没有放置 | 先选中方块；已有方块或与身体重叠会被拒绝，留意屏幕提示 |
| 碰撞或跳跃异常 | 先运行 test；检查 Player 的脚底坐标与 CollisionSystem 的 ±0.5 边界 |
| 选中的方块类型不对 | 查看选择栏高亮；编号和材质统一在 blockTypes 中配置 |

## 第一阶段范围

这是小型创造式沙盒：方块无限使用、逐次点击操作、不含生存数值。世界修改暂不保存，刷新页面会恢复为400块草地。没有随机地形、无限区块、背包、合成、怪物、联网或存档。
